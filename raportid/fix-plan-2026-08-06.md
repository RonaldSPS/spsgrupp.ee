## Phase 3 — Performance: caching first, then LCP (day 2–4)

### 3B. Durable fix — make the site prerenderable (1–2 days, the real solution)

Root cause: `app/layout.tsx:105` `await headers()` → entire site dynamic. Only two consumers of `x-sps-locale`: root layout (locale/messages) and `lib/actions.ts` (server actions — inherently dynamic, fine).

| # | Step | Detail | Risk control |
|---|---|---|---|
| 3B.1 | Verify Next 16 root-locale mechanics | Next 16 root layouts can't read route params; check whether `rootParams` (root-level params API) is stable in 16.3. Spike: 30-min local build test. | If unavailable → do 3B via route-group alternative or stay on 3A permanently |
| 3B.2 | Restructure `/en`, `/ru` under `app/[locale]/[[...slug]]` with `generateStaticParams: [{locale:'en'},{locale:'ru'}]` | ET stays at root (no param → `et`). Root layout reads locale via rootParams instead of `headers()`. `proxy.ts` keeps setting `X-SPS-Locale` only for `lib/actions.ts` consumers. | Byte-diff gate: rendered HTML for all 140 URLs must match baseline byte-for-byte (excluding cache headers) |
| 3B.3 | Prerender + ISR | Static generation for all marketing pages; `export const revalidate = 300` on DB-backed pages (home reviews, careers jobs, blog). | `next build` output shows pages as static/ISR; preview: `X-Vercel-Cache: HIT`, TTFB < 100 ms |
| 3B.4 | Keep `trailingSlash`, all redirects, RU Cyrillic slugs | Registry-driven; re-run `i18n:parity` + `seo:check` | All green |

**Rollback:** 3B is branch-isolated; 3A stays as the fallback layer either way.
