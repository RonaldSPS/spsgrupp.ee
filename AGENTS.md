# Project: SPS Grupp ET/EN/RU marketing site (Next.js 16 App Router)

- **Rendering:** whole site is SSG+ISR (see "Rendering & caching" in `ARCHITECTURE.md`): unified `app/[locale]/[[...slug]]` catch-all with `next/root-params`, proxy rewrites ET URLs to internal `/et`, marketing components live in `app/_pages/`, ET metadata in `lib/et-metadata-registry.ts`. Server actions still read `X-SPS-Locale` from the proxy header.
- **Page architecture:** one-pattern system — see the "Page system" section of `ARCHITECTURE.md`. Single page registry: `lib/pages/registry.ts`; per-page content: `lib/pages/definitions/`; 26 detail pages = shells → `app/components/templates/ServiceDetailTemplate.tsx`.
- **Commands:** `npm run dev` · `npm run lint` · `npx tsc --noEmit` · `npm test` (includes `i18n:validate`) · `npm run i18n:parity` (needs a running server) · `npm run build` · `npx tsx scripts/generate-llms-txt.ts` (after registry/price changes) · `npx tsx scripts/sync-translation-fallbacks.ts` (after translation changes in admin).
- **Preserve every public URL/slug** (incl. RU slugs and `/koolide-koristamine`), all metadata/canonicals/hreflang, and rendered byte output on refactors (byte-diff gate).
- **Gotchas:** `tsconfig` type-checks `raportid/` (no stray `.ts/.tsx` backups there); long-running dev servers must be started detached (`Start-Process`), not `Start-Job` (jobs die with the shell); `npm run build` workers can crash with stray node processes — kill strays and retry; **incremental builds lie** — before any gate (byte-diff, deploy) delete `.next` and rebuild clean (stale prerender files and turbopack cache produce mixed old/new output); **kill old `next start` servers before starting a new one** (EADDRINUSE + serving a stale build against an overwritten `.next` = confusing 500s); Supabase pooler stalls under parallel build workers — all page-path DB reads have 2.5 s timeouts + JSON fallbacks (`data/admin-*.json`); `spsgrupp-live` auto-pauses (EN/RU reviews/jobs go blank — restore via Supabase API, then re-run `scripts/sync-translation-fallbacks.ts`); trailing-slash normalization precedes the proxy (no-slash admin URLs 308 first, gate 401s on the hop — probe with redirect-following); `%2F`-in-path requests that decode to real API routes 500 inside **Vercel's** serverless-middleware module lookup (platform artifact, fails closed, not fixable in app code; local `next start` 404s).
- **Admin & forms:** `/spsadmn/` = blog, tööle, testimonials, paringud, seaded. Contact/career submissions are stored in `form_submissions` (migrations `drizzle/0005_form_submissions.sql` + `drizzle/0006_submission_financials.sql` + `drizzle/0007_submission_spam_flag.sql` must be applied to live DB) via `lib/form-submissions.ts`; JSON fallback `data/form-submissions.json` when DB unset/unavailable. Contact submissions carry admin-edited `fee`/`profit`/`notes` (Tasu/Kasum/Märkused columns + period totals in paringud, saved via `PATCH /api/spsadmn/submissions/[id]`). List + CSV export at `/api/spsadmn/submissions[/export]` (formula-injection-escaped). Form recipient emails are admin settings: `email_recipients` (contact) and `career_email_recipients` (career), read in `lib/actions.ts` with fallbacks `info@`/`personal@spsgrupp.ee`. **Spam:** every submission is scored by `lib/spam.ts` (links/blocklist/disposable domains); flagged rows save with `is_spam` (badge + "Spämm" filter in paringud) but send NO emails, with fake success to the submitter. **Auto-replies:** both forms send the submitter a localized confirmation (settings `autoreply_{contact|career}_enabled` + `autoreply_{kind}_{subject|body}_{et|en|ru}` in Seaded → "Automaatvastused"; empty fields fall back to built-in drafts in `lib/actions.ts`), capped at one per address per form per 24 h via `hasRecentSubmission()` (fails closed on storage errors); auto-reply failures only log, never fail the form; `replyTo` points at the form's recipient setting. Form emails go through the Resend HTTPS API in `lib/email.ts` (`RESEND_API_KEY`/`Resend_API`, sender `EMAIL_FROM`, optional `replyTo` → `reply_to`); the sender domain must be verified in Resend — until then only `onboarding@resend.dev` → account-owner address works.
- **Admin auth resilience:** login/token validation read `admin_users` with a 5 s timeout; on failure the postgres singleton is reset (`resetDbConnection()` in `lib/db`) so the next attempt reconnects, and auth falls back to `data/admin-users.json` (gitignored — contains password hashes; refreshed by `syncAdminUsersSnapshotFromDb()` after every admin-user mutation). A 10 s down-cooldown keeps outage-mode requests fast. If the store is fully unreachable, login returns 503 "Andmebaasi ühendus ebaõnnestus" — never the misleading "Vale parool". Env `ADMIN_PASSWORD` login always works without any store.
