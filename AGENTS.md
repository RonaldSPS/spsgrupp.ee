# Project: SPS Grupp ET/EN/RU marketing site (Next.js 16 App Router)

- **Rendering:** whole site is SSG+ISR (see "Rendering & caching" in `ARCHITECTURE.md`): unified `app/[locale]/[[...slug]]` catch-all with `next/root-params`, proxy rewrites ET URLs to internal `/et`, marketing components live in `app/_pages/`, ET metadata in `lib/et-metadata-registry.ts`. Server actions still read `X-SPS-Locale` from the proxy header.
- **Page architecture:** one-pattern system — see the "Page system" section of `ARCHITECTURE.md`. Single page registry: `lib/pages/registry.ts`; per-page content: `lib/pages/definitions/`; 26 detail pages = shells → `app/components/templates/ServiceDetailTemplate.tsx` (28 detail pages as of 26.08.2026: +/koristusteenus/hoolduskoristus, +/puhastusteenused/suurpuhastus — when adding one, touch ALL of: `lib/pages/registry.ts`, `lib/page-registry.ts`, `lib/localized-page-registry.tsx`, `lib/et-metadata-registry.ts`, `lib/pages/definitions/index.ts` + new definition file, `lib/metadata-registry.ts` (ET+EN+RU), `scripts/i18n-validate.ts` DEFINITION_COUNT, Navbar/Footer links + `megaMenu.*` keys in messages, then regenerate llms.txt).
- **Commands:** `npm run dev` · `npm run lint` · `npx tsc --noEmit` · `npm test` (includes `i18n:validate`) · `npm run i18n:parity` (needs a running server) · `npm run build` · `npm run db:restore` (wake paused Supabase via Management API + verify queries) · `npm run report:analytics` (GA4 + Ads + GSC digest — needs the service-account key, see Analytics bullet) · `npx tsx scripts/generate-llms-txt.ts` (after registry/price changes) · `npx tsx scripts/sync-translation-fallbacks.ts` (after translation changes in admin).
- **Preserve every public URL/slug** (incl. RU slugs and `/koolide-koristamine`), all metadata/canonicals/hreflang, and rendered byte output on refactors (byte-diff gate).
- **Gotchas:** `tsconfig` type-checks `raportid/` (no stray `.ts/.tsx` backups there); long-running dev servers must be started detached (`Start-Process`), not `Start-Job` (jobs die with the shell); `npm run build` workers can crash with stray node processes — kill strays and retry; **incremental builds lie** — before any gate (byte-diff, deploy) delete `.next` and rebuild clean (stale prerender files and turbopack cache produce mixed old/new output); **kill old `next start` servers before starting a new one** (EADDRINUSE + serving a stale build against an overwritten `.next` = confusing 500s); Supabase pooler stalls under parallel build workers — all page-path DB reads have 2.5 s timeouts + JSON fallbacks (`data/admin-*.json`); `spsgrupp-live` auto-pauses (EN/RU reviews/jobs go blank + DB-user admin auth fails on Vercel — no snapshot file there) — prevention: Vercel Cron hits `app/api/cron/keepalive` daily (`vercel.json`, requires `CRON_SECRET` env in Vercel, path keeps trailing slash to skip the 308); manual wake-up: `npm run db:restore` (local) or Seaded → Andmebaas → „Käivita andmebaas" (live, `app/api/spsadmn/db` GET status + POST restore, polls until ACTIVE + DB answers — both need `SUPABASE_ACCESS_TOKEN` + `SUPABASE_PROJECT_REF` in Vercel env, then re-run `scripts/sync-translation-fallbacks.ts`); only a paid Supabase plan disables pausing entirely; trailing-slash normalization precedes the proxy (no-slash admin URLs 308 first, gate 401s on the hop — probe with redirect-following); `%2F`-in-path requests that decode to real API routes 500 inside **Vercel's** serverless-middleware module lookup (platform artifact, fails closed, not fixable in app code; local `next start` 404s).
- **Admin & forms:** `/spsadmn/` = blog, tööle, testimonials, paringud, seaded. Contact/career submissions are stored in `form_submissions` (migrations `drizzle/0005_form_submissions.sql` + `drizzle/0006_submission_financials.sql` + `drizzle/0007_submission_spam_flag.sql` + `drizzle/0008_submission_page_url.sql` + `drizzle/0009_submission_gclid.sql` must be applied to live DB) via `lib/form-submissions.ts`; JSON fallback `data/form-submissions.json` when DB unset/unavailable. Contact submissions carry admin-edited `fee`/`profit`/`notes` (Tasu/Kasum/Märkused columns + period totals in paringud, saved via `PATCH /api/spsadmn/submissions/[id]`). Each submission also records `page_url` — the page it was sent from (hidden `page_url` field in ContactForm/CareerForm, sanitized to http(s)/root-relative in `lib/actions.ts`, shown as "Leht" column in paringud). Contact submissions also carry `gclid` — the Google Ads click id captured by a hidden `gclid` field in ContactForm (`getGclid()` in `app/components/analytics/gclid.ts` reads the landing URL param, falling back to the Conversion Linker `_gcl_aw` cookie; consent-safe: no ad_storage → no cookie → empty value), sanitized in `lib/actions.ts`, shown under the Leht cell in paringud and included in the notification email + CSV export. Career form intentionally has no gclid. Rows can be bulk-selected with checkboxes and deleted via `DELETE /api/spsadmn/submissions` with `{ ids: number[] }`. List + CSV export at `/api/spsadmn/submissions[/export]` (formula-injection-escaped). Form recipient emails are admin settings: `email_recipients` (contact) and `career_email_recipients` (career), read in `lib/actions.ts` with fallbacks `info@`/`personal@spsgrupp.ee`. **Spam:** four layers — (1) honeypot `website_url`, (2) timing trap (`form_started_at` hidden input stamped with `Date.now()` on mount in both forms; submissions < 3 s old get fake success without saving; missing/invalid = no-JS, check skipped), (3) Cloudflare Turnstile in invisible mode (`lib/turnstile.ts`, widget auto-rendered in ContactForm/CareerForm only when `NEXT_PUBLIC_TURNSTILE_SITE_KEY` is set; server verifies `cf-turnstile-response` only when `TURNSTILE_SECRET_KEY` is set — until then it's a full no-op; once set it FAILS CLOSED: missing/invalid token → generic localized sendFailed error, nothing saved; `challenges.cloudflare.com` is whitelisted in the proxy.ts CSP script/frame/connect-src — never strip it), (4) content scoring by `lib/spam.ts` (links/blocklist/disposable domains/gibberish detection — random-looking single-token names/messages and generated companies like "Vajxcoy LLC", matched on original casing; the scorer lowercases for phrase matching, so gibberish checks use `input.*` raw values). Content-flagged rows save with `is_spam` (badge + "Spämm" toggle filter in paringud (pill buttons: Kõik/Kontaktivorm/Tööavaldus form filter + separate Spämm toggle, combinable — `form` & `spam=1` query params both supported by the API/CSV export). Long Sõnum/Leht cell content is collapsed with a "Näita rohkem" expand toggle (`ExpandableText` in the paringud page) so tall entries can't stretch rows. The paringud table is `table-fixed` with user-resizable columns (drag a header's right edge; widths persist in localStorage `sps_paringud_col_widths`, "Lähtesta veerulaiused" resets — `TABLE_COLUMNS` and `DEFAULT_COL_WIDTHS` in the page are index-matched, keep them in sync); the wrapper scrolls horizontally on narrow screens — this only works because the admin layout root has `min-w-0`: body is `flex flex-col` in root-shell, and without it the flex item won't shrink below the table width, so the page grows and `body { overflow-x: hidden }` clips the table instead of the wrapper scrolling) but send NO emails, with fake success to the submitter. **Auto-replies:** both forms send the submitter a localized confirmation (settings `autoreply_{contact|career}_enabled` + `autoreply_{kind}_{subject|body}_{et|en|ru}` in Seaded → "Automaatvastused"; empty fields fall back to built-in drafts in `lib/actions.ts`), capped at one per address per form per 24 h via `hasRecentSubmission()` (fails closed on storage errors); auto-reply failures only log, never fail the form; `replyTo` points at the form's recipient setting. Form emails go through the Resend HTTPS API in `lib/email.ts` (`RESEND_API_KEY`/`Resend_API`, sender `EMAIL_FROM`, optional `replyTo` → `reply_to`); the sender domain must be verified in Resend — until then only `onboarding@resend.dev` → account-owner address works.
- **Analytics & ads:** full connection/rebuild guide in `ANALYTICS.md`. - **Admin auth resilience:** login/token validation read `admin_users` with a 5 s timeout; on failure the postgres singleton is reset (`resetDbConnection()` in `lib/db`) so the next attempt reconnects, and auth falls back to `data/admin-users.json` (gitignored — contains password hashes; refreshed by `syncAdminUsersSnapshotFromDb()` after every admin-user mutation). A 10 s down-cooldown keeps outage-mode requests fast. If the store is fully unreachable, login returns 503 "Andmebaasi ühendus ebaõnnestus" — never the misleading "Vale parool". Env `ADMIN_PASSWORD` login always works without any store. New admin users are created in Seaded → Kasutajad with just e-mail + password + role (no name field — `displayName` is auto-derived from the e-mail); `POST /api/spsadmn/seaded/admins` sends the new user a notice e-mail with their credentials + login URL via Resend (response carries `emailSent`; failure only logs + UI warns, creation never fails because of e-mail).
